## 1. Executive Summary

This report documents the architectural refinement of the **Canonical Scientific Data Model** for ORCA Web Lab prior to independent final auditing. The canonical data model has been refined from a generic application-state container into an immutable, versioned, machine-readable **scientific analysis data contract**.

All 22 verification test cases in `tests/test_canonical_scientific_schema.py` have passed with 100% compliance.

---

## 2. Previous Architecture vs. Refined Architecture

### Previous Architecture (State Container):
In the initial prototype, editor states (3D builder atoms, canvas viewport tokens, wizard forms) and calculation outputs were mixed into a single generic `record_type`. There was no structural separation between user intent (e.g. requested reaction stoichiometry) and observed quantum chemical observables.

### Refined Architecture (Scientific Contract):
The canonical model now formally separates 4 primary domain entities:
1. **`AnalysisRecord` (`record_type: "analysis_record"`):** The primary scientific ground truth containing parsed ORCA outputs (`analysis_opt`, `analysis_freq`, `analysis_sp`, `analysis_ir`, `analysis_uv`, `analysis_nmr`).
2. **`ReactionDefinition` (`record_type: "reaction_definition"`):** User-defined reaction stoichiometry and thermodynamic conditions.
3. **`WorkflowRecord` (`record_type: "workflow_record"`):** Multi-step calculation execution graph (`OPT -> FREQ -> SP`) and geometry handoffs.
4. **`CalculationRecord` (`record_type: "calculation_record"`):** Requested input parameters linked to resulting `analysis_record_id`.

---

## 3. AnalysisRecord as Primary Scientific Ground Truth

The canonical model is constructed directly from parser model objects (`MoleculeData`, `JobData`, `CalcMetadata`) generated by `OrcaParser`.
- Coordinates are stored in high-precision Angstrom units with SHA-256 Cartesian table fingerprints.
- Energies, zero-point corrections, enthalpies, and Gibbs free energies are recorded with explicit `hartree` units.
- Harmonic vibrational modes and TD-DFT excited states are isolated from presentation layers.
- Raw, parsed, derived, and assigned spectral modes are stored in distinct typed arrays.

---

## 4. Deterministic Content Hash vs Record Identity

To ensure scientific reproducibility and robust deduplication across machine learning datasets:
- **`record_id`:** Stable or generated logical UUID.
- **`content_hash`:** Deterministic SHA-256 hash computed over canonicalized scientific payload.

### Invariance Rules:
- Identical chemical structures, geometries, and computed energies produce identical `content_hash` values.
- Modifying non-scientific volatile metadata (such as timestamps or UUIDs) produces the exact same `content_hash`.
- Modifying Cartesian coordinates or electronic energies alters the `content_hash`.

## 6. Machine Learning Target-Leakage Protection

`tools/export_training_jsonl.py` implements fail-closed validation against data leakage across 4 supported task types:
1. `molecular_property_prediction`: Inputs restricted to SMILES, formula, charge, multiplicity, and coordinates; targets (HOMO, LUMO, dipole, Gibbs energy) are strictly forbidden in input features.
2. `reaction_energy_prediction`: Inputs restricted to reaction equation, participant names, and stoichiometry; reaction energies ($\Delta H, \Delta G, K_{\text{eq}}$) are forbidden in inputs.
3. `vibrational_spectrum_prediction`: Vibrational frequencies and IR intensities are forbidden in input representations.
4. `ir_peak_assignment_classification`: Functional group labels and confidence ratings are forbidden in input features.

Each JSONL record includes a `split_group_key` (InChIKey or canonical formula) to prevent cross-split data leakage during model training.

## 7. Real Analyzer Normalization Verification

`tools/normalize_scientific_json.py` was validated against real ORCA 6.1 calculation outputs (`orca_engine/data/orcafile/orca6.1/nap.out`). The normalizer successfully mapped 100% of parsed coordinates, electronic energies, dipole moments, and vibrational modes into the canonical `AnalysisRecord` schema with zero information loss.

A structured `migration_report` is returned alongside each record, detailing:
- `mapped_fields`: Successfully mapped standard fields.
- `transformed_fields`: Normalized units and structures.
- `omitted_fields`: Scrubbed security tokens and UI presentation artifacts.
- `warnings`: Actionable migration notifications.

## 9. Limitations and Future Considerations

1. **Cartesian Alignment:** The `content_hash` calculates the SHA-256 fingerprint of Cartesian coordinate tables. It is translationally and rotationally frame-dependent. Rotational/translational invariant canonical graph hashes can be added in a future minor release.
2. **Projected Density of States (PDOS):** While frontier molecular orbitals (HOMO, LUMO, gap) are extracted and normalized, full projected density of states grid datasets are currently stored in auxiliary artifact archives rather than inline JSON.
